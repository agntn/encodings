## Why this exists

Paste a base58 string into a chat and ask what it says. The model will tell you. Confidently. It reads the shape, not the bytes, and for base58 the shape tells you nothing. Encodings are arithmetic, and a language model is bad at arithmetic it can't see.

So the model should call something that does the arithmetic. `@agntn/encodings` is that something. Same thing in your TypeScript, your terminal and your agent.

Every codec here is written from its spec. RFC 4648 for base16, base32 and base64. RFC 9285 for base45. BIP173 and BIP350 for bech32. The reference code where the reference code is the spec, like basE91. No `@scure/base`, no `bs58`, no codec library underneath. The one dependency is `@agntn/hashes`, for the double SHA-256 behind Base58Check.

## Install

```bash
pnpm add @agntn/encodings
```

Node.js 26 or newer. The library itself touches nothing from `node:*`, which is why this site runs it in your browser.

## First calls

```ts
import { decode, encode, identify } from "@agntn/encodings";

encode("base64", "hello world!");
// "aGVsbG8gd29ybGQh"

decode("base64", "aGVsbG8gd29ybGQh").bytes;
// Uint8Array(12), "hello world!" in UTF-8

identify("JBSWY3DPEBLW64TMMQ======")[0];
// { encoding: "base32", confidence: 0.593, text: "Hello World", … }
```

`encode` takes a string, read as UTF-8, or a `Uint8Array`. `decode` always gives bytes back. Plus `details` for whatever the text carried besides data. A bech32 prefix, a witness version, a uuencode file name. Don't know the encoding? `identify` tries them all and shows its reasoning.

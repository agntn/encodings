title: CLI
description: encode and decode and identify and list from the terminal. Bytes go to stdout raw and everything else goes to stderr
---

## Install or run once

```bash
pnpm add -g @agntn/encodings
npx @agntn/encodings identify 'JBSWY3DPEBLW64TMMQ======'
```

## Commands

| Command | Does |
| --- | --- |
| `encodings encode <encoding> <input>` | Write text or bytes in an encoding |
| `encodings decode <encoding> <text>` | Read it back into bytes |
| `encodings identify <text>` | Rank the encodings it decodes in, or `--peel` them off layer by layer |
| `encodings list [encoding]` | Every encoding, one family with `--family`, or one with its alphabet and options |
| `encodings mcp` | The [MCP server](/guide/agents) over stdio |

`-` instead of the input reads stdin. `encode` takes it byte for byte. `decode` and `identify` drop one trailing line break, the one your shell pipe added.

Text that starts with `-`? Ascii85, Z85 and the URL alphabet of base64 all write one. The parser takes it for an option. Put it after `--`:

```bash
encodings decode base85 --alphabet ascii85 -- -Y7,
# 'em
```

## Stdout is the answer

```bash
encodings encode base64 'hello world!'
# aGVsbG8gd29ybGQh

encodings decode base64 aGVsbG8gd29ybGQh
# hello world!
```

`decode` writes the raw bytes, like `base64 -d` does. Pipe them into a file, into `xxd`, into the next command. Binary in your terminal? Add `-o hex` or `-o base64`.

Whatever the text carried besides data goes to stderr. One `key: value` per line. Stdout stays clean.

```bash
encodings decode bech32 bc1qw508d6qejxtdg4y5r3zarvary0c5xw7kv8f3t4 -o hex
# prefix: bc                                  (stderr)
# witnessVersion: 0                           (stderr)
# 751e76e8199196d454941c45d1b3a323f1433bd6
```

Those values come from the text, so they're escaped before they reach your terminal. A uuencode file name with an escape sequence shows up as `\u001b`. Not as a recolored prompt.

## Bytes in

```bash
encodings encode hex --input-format base64 aGk=
# 6869

encodings encode base58 0062e907b15cbf27d5425399ebf6f0fb50ebb88f18 --input-format hex --check
# 1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa
```

`--input-format` is `utf8` by default. `hex` and `base64` encode the bytes they spell.

## Options

A flag only reaches the encodings that declare it. Anything else is an error.

```bash
encodings encode bech32 gm --prefix test
# test1vaks69jerm

encodings encode base64 gm --prefix bc
# Invalid option prefix=bc: base64 does not take it
```

Not sure what one takes? `encodings list <encoding>` shows it. `--alphabet`, `--check`, `--m`, binary's `--symbols`, `--bits` and `--order`, and base256's `--symbols`, `--sample` and `--multibase` change how the text reads, so `decode` takes them too:

```bash
encodings decode base32 CPNMUOJ1E8 --alphabet hex
# foobar
```

## Identify

```bash
encodings identify 1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa -n 2
# 0.574  base58 --check              0062e907b15cbf27d5425399ebf6f0fb50ebb88f18  (checksum matches)
# 0.043  base32 --alphabet=crockford 0a83fb05d62de0e7844da5b4fd04b90d3676876faa
```

Score, encoding, the decoded value as text or hex, and the reasons. `-n` sets how many. A candidate that needed an option carries its flag, `base32 --alphabet=hex` or `base58 --check`, ready for `decode`.

Two layers deep? `--peel` goes down, outermost first.

```bash
encodings identify --peel 5958523059574e7249474630494752686432343d
# 0.414  hex                         "YXR0YWNrIGF0IGRhd24="  (decodes to readable text, fits a 16-character alphabet)
# 0.571  base64                      "attack at dawn"  (padding fits the block length, decodes to readable text)
```

Here `-n` caps the layers, ten by default. A last line with `unconfirmed guess` in the reasons is only that, a [guess](/guide/identify#encoded-twice-peel-it).

## Exit codes

`0` when it worked. `1` with one line on stderr when it didn't. A bad character, a checksum that doesn't match, an unknown encoding. Or `identify` finding nothing at all.

```bash
encodings decode base58 1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNb --check
# base58: checksum does not match
echo $?
# 1
```

Colors only when both stdout and stderr are a terminal that takes them. A pipe gets plain text.

---
title: Base64url
description: RFC 4648 base64 with - and _ for URLs and file names. Unpadded the way JWT writes it
---

::encoding-facts{name="base64url"}
::

Base64 with `-` and `_` instead of `+` and `/`. It survives a URL and a file name. No padding, because that's what JWTs write.

```ts
encode("base64url", '{"alg":"HS256","typ":"JWT"}');
// "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9"
```

Look familiar? Every JWT starts with `eyJ`, because every JWT starts with `{"`. Decoding takes the padding when it's there. Text without `-` or `_` is valid base64 and base64url at once, which is why `identify` calls those a tie.

::encoding-facts{name="base32"}
::

Letters and the digits 2 to 7. It survives a file system that ignores case. It survives a person who confuses `0` with `O`, too. The secret behind your authenticator app? Base32. Onion v3 addresses as well.

```ts
encode("base32", "foobar");  // "MZXW6YTBOI======"
```

That's the RFC 4648 test vector. Five bytes become eight characters, and the last block pads with `=`. Decoding takes lowercase and the text with or without padding. Wrong padding is an error, though. Six `=` where the length needs four means something got mangled on the way.

And who pads anyway? Stellar addresses don't. TOTP secrets don't either. Pass `padding: false` and you don't have to:

```ts
encode("base32", "foobar", { padding: false });  // "MZXW6YTBOI"
```

## The hex alphabet

The same RFC has a second alphabet, `0` to `9` and `A` to `V`. Why bother? Order. Sort the encoded strings and they line up exactly like the bytes. Plain base32 can't do that.

```ts
encode("base32", "foobar", { hex: true });           // "CPNMUOJ1E8======"
decode("base32", "CPNMUOG=", { hex: true }).bytes;  // "foob"
```

Decoding needs `hex` too. `CPNMUOG=` fits both alphabets, and without the option it's four other bytes. No error, just wrong. DNSSEC writes NSEC3 owner names in this alphabet, unpadded, so DNS wants `padding: false` as well.

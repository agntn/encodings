---
title: Base64
description: RFC 4648 base64. Three bytes as four characters padded with = and line breaks skipped on decode
---

::encoding-facts{name="base64"}
::

The one you've seen a million times. Three bytes, four characters, `=` to fill the last block.

```ts
encode("base64", "hello world!");             // "aGVsbG8gd29ybGQh"
decode("base64", "aGVsbG8g\r\nd29ybGQh").bytes;  // "hello world!", line break and all skipped
```

Decoding skips whitespace, so a MIME body or a PEM block decodes as it is. It takes the text without padding too. The wrong padding, though? `Zg=` is one `=` short, and you'll hear about it. Characters from base64url are an error here, not a guess.

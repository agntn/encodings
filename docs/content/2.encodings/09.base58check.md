Base58 with a seatbelt. The payload, then the first four bytes of its double SHA-256.

```ts
hex.encode(base58check.decode("1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa"));
// "0062e907b15cbf27d5425399ebf6f0fb50ebb88f18"
```

The genesis address: version `0x00`, then the HASH160 of Satoshi's key. Change one character and `decode` throws `ChecksumError`. The double SHA-256 comes from [@agntn/hashes](https://hashes.agntn.dev), the one dependency this package has.

The version stays in the payload. Is `0x80` a WIF key and `0x05` a P2SH address? Sure, but that's network knowledge, and it lives in [@agntn/keys](https://keys.agntn.dev). This codec checks the checksum and hands you the bytes.

## Another hash, another alphabet

Some chains keep the format and swap one part. Decred ends its addresses with double BLAKE-256. So `base58check` turns down every one of them. Correctly, in a way. `createBase58check` takes the hash and builds the codec:

```ts
import { blake256 } from "@agntn/hashes/blake256";
import { createBase58check } from "@agntn/encodings/base58";

const decred = createBase58check(blake256);
hex.encode(decred.decode("DsUZxxoHJSty8DCfwfartwTYbuhmVct7tJu"));
// "073f2789d58cfa0957d206f025c2af056fc8a77cebb0"
```

Pass the hash once. The codec runs it twice and keeps four bytes, like Bitcoin does with SHA-256. And the version is two bytes here, `073f`.

The XRP Ledger goes the other way. Double SHA-256 stays, the alphabet changes. `base58-ripple` reads that alphabet and checks nothing. A typo comes back as bytes. Want the checksum? Hand over the alphabet too:

```ts
import { sha256 } from "@agntn/hashes/sha2";

const RIPPLE = "rpshnaf39wBUDNEGHJKLM4PQRST7VWXYZ2bcdeCg65jkm8oFqi1tuvAxyz";
const xrp = createBase58check(sha256, RIPPLE);
xrp.decode("rHb9CJAWyB4rj91VRWn96DkukG4bwdtyTi");
// throws "base58check: checksum does not match"
```

That's the genesis account with its last character bumped. Got an alphabet without 58 distinct characters? `InvalidOptionError`, right at the call. The hash stays your import. This package doesn't grow a BLAKE-256 of its own.

`createBase58check` comes from `@agntn/encodings/base58` only.
